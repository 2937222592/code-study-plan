## 1. 项目概览

- **定位**：面向编程初学者的「学习陪跑系统」——AI 应用开发岗位的路线、计划、资料、课件互动与 AI 助教
- **v1 范围（冻结）**：AI 应用开发岗位内容 + 账号与进度 + 学习计划/打卡 + 资料/课件（标注、笔记、章节讨论区）+ AI 助教 + 系统管理后台
- **技术栈**：FastAPI + SQLAlchemy + SQLite；Vue 3 + Vite（JavaScript）；**LangChain（AI 服务层）** + DeepSeek API；Docker Compose
- **验收标准**：见需求文档第 11 节

## 2. 团队分工（明确责任，不允许重叠）

| 角色 | 负责人 | 职责范围 |
|---|---|---|
| **前端开发** | **Codex（我）** | **前端先行**：先从「注册登录 + 系统管理」开始做（认证页 + 系统管理全部子模块页面），再做用户端业务页面；负责接口契约与 mock 数据联调 |
| **后端开发** | **你的团队** | 全部后端：认证、内容/进度/课件/讨论/AI/管理 API、数据模型与迁移、Docker 部署 |
| 产品 / 内容 | 产品负责人 | 需求维护、内容制作（概念卡/资源/课件/小任务/FAQ 数据） |
| 测试 | 前端 + 后端共同 | 联调验收、E2E 用例执行 |

**协作关键点：**
- **接口契约先行**：后端未开发前，前端按冻结的 OpenAPI 契约 + mock 数据开发页面；后端按同一契约实现，联调时零返工
- 一切变更走分支 + PR；接口变更必须同步更新契约文档
- 模块 owner 制：每个模块由对应负责人合并

## 3. 实施顺序（按用户要求，不可颠倒）

| 顺序 | 内容 | 产出 | 负责 |
|---|---|---|---|
| **第 1 步** | **前端先行 · 注册登录 + 系统管理**（先做） | 认证页（登录/注册/忘记密码）+ 管理后台全部页面（数据概览/内容/课件/讨论/投诉/系统管理分组：用户/角色/菜单/设置/日志，含子页面） | 前端 Codex |
| **第 2 步** | **前端 · 用户端页面**（全部） | 路线、技能详情、课件阅读、讨论区、AI 助教、学习计划、我的笔记、我的统计（基于契约 + mock） | 前端 Codex |
| **第 3 步** | **后端实现** | 按已冻结契约补齐全部后端接口、数据模型、AI 服务、部署 | 后端团队 |
| **第 4 步** | 联调 / 测试 / 上线 | 通过验收标准，试运行 | 双方 |

> 说明：页面全部基于「接口契约 + mock 数据」先行开发，因此后端放到最后做不会阻塞前端。

## 8. 接口契约先行（关键协调机制）

- 统一 REST：`/api/*`，响应结构 `{ code, message, data }`
- 第 1 步冻结 **OpenAPI 契约**（含管理模块与用户端全部接口），放入 `docs/API.md`
- 前端页面全部基于契约 + mock 数据开发；后端按契约实现
- 接口变更流程：提出 → 更新契约 → 双方确认 → 再改代码

## 11. 测试计划

- **前端（Codex）**：页面在 mock 下的交互自测；E2E 用例编写（Playwright）
- **后端（团队）**：pytest 单测（认证/权限/AI mock/限额）、接口集成测试
- **联调**：契约一致性校验、核心旅程 3 条（新用户首日学习；课件笔记+讨论；AI 答疑）

## 12. 风险与应对

| 风险 | 应对 |
|---|---|
| 前端 mock 与后端实现偏差 | 契约先行 + 契约校验用例 |
| 内容制作量大 | 分批录入，S0-S2 优先；后台先行可边录边用 |
| LangChain 版本漂移 | 锁定版本、AI 调用收敛在 ai_service |
| 课件版权 | 只收录开源/自制，标注来源，投诉下架 |
| AI 成本 | 日限额、缓存、开发期 mock |
